# ELSDTU 需求边界 v0.1

状态：待业务确认。本文是立项与原型验证的工作基线，不代表用户已确认所有细节。

## 1. 产品目标

建设一个管理多台边缘计算网关的中台，让实施人员能够在云端配置现场设备、点位、监控画面和常见处理流程，并将配置发布到指定网关。网关断网时应能按已生效配置继续采集和执行本地流程。

首版重点验证一条完整链路：**网关注册 → 接入现场设备 → 采集点位 → 配置流程 → 发布到网关 → 查看数据与告警**。

## 2. 目标用户与权限（暂定）

| 角色 | 主要任务 |
| --- | --- |
| 平台管理员 | 管理租户、平台用户、全局运行状态和权限策略 |
| 项目管理员 | 管理本项目网关、设备、成员与发布权限 |
| 实施工程师 | 配置协议、设备点位、流程和组态页面，执行测试与发布 |
| 运维人员 | 查看网关状态、日志、告警、配置版本，执行授权的回滚 |
| 只读查看者 | 查看组态画面、实时数据和历史告警 |

**待确认：**是否需要面向外部客户的多租户 SaaS；若仅企业内部使用，可先简化租户管理。

## 3. 首版范围（P0）

| 编号 | 能力 | 可验收结果 |
| --- | --- | --- |
| P0-01 | 网关注册、认证、心跳、分组 | 新网关可激活；平台可显示在线状态和最近心跳 |
| P0-02 | 现场设备与点位管理 | 能创建网关下挂设备，配置点位地址、类型、采集周期和单位 |
| P0-03 | 至少一种现场协议接入 | 使用真实设备或模拟器稳定采集数据；首选 Modbus TCP 作为验证协议，待确认 |
| P0-04 | 实时与历史数据 | 能查看点位当前值及指定时间段的曲线 |
| P0-05 | 基础零代码流程 | 支持采集输入、数据转换、阈值判断、告警和上报节点 |
| P0-06 | 流程版本发布 | 云端保存草稿，校验后下发指定网关；显示成功或失败回执 |
| P0-07 | 网关本地执行与回滚 | 断网后已发布流程继续运行；无效版本不替换当前版本；可回滚 |
| P0-08 | 基础云组态 | 拖拽数值、状态灯、曲线、告警列表等组件并绑定点位 |
| P0-09 | 基础告警与审计 | 触发、查看、确认告警；记录配置发布和设备写入操作 |

## 4. 下一阶段候选（P1）

- OPC UA、Modbus RTU、MQTT 等更多协议和驱动插件管理。
- 批量网关导入、设备模板、点位模板、流程模板。
- 流程模拟运行、灰度发布、发布前后版本对比。
- 网关远程诊断、日志检索、固件或代理程序升级。
- 更完整的多租户隔离、细粒度权限和开放 API。

这些能力会在 P0 验证后重新排序，不作为首版验收的默认承诺。

## 5. 本阶段不纳入

- 用拖拽流程覆盖任意复杂算法或任意第三方软件部署。
- 为所有工业协议开发自有驱动。
- 在未经设备侧确认的情况下自动执行高风险控制动作。
- 一开始就建设跨地域高可用集群。

## 6. 关键使用场景

### 场景 A：网关上线与采集

实施工程师激活网关，为其创建一台下挂设备与若干点位，配置采集周期。平台持续显示网关在线状态、点位当前值和历史值。

### 场景 B：零代码告警

工程师拖拽流程，设置“温度连续 3 次超过阈值则告警”，发布到一台网关。网关按生效版本在本地判断，平台显示告警及对应的流程版本。

### 场景 C：断网与错误发布

网关断网后继续执行场景 B 的流程；恢复连接后补传可恢复的数据。下发不合法的新配置时，网关拒绝切换并保留上一版本，平台显示失败原因。

### 场景 D：组态查看

项目成员打开监控页面，看到与点位绑定的实时数值、状态和曲线，并能查看当前告警。

## 7. 核心约束与原则

1. 云端负责编辑、校验、版本管理和发布；网关负责现场采集与本地执行。
2. 流程配置和组态页面分别管理版本；两者共用设备及点位模型。
3. 设备写入操作须经过权限检查、参数范围校验和审计；首版以只读采集与告警为主。
4. 网关身份、配置版本和命令回执必须可追踪；敏感凭据不写入流程明文。
5. 先验证现有开源项目的能力，再决定二次开发边界。候选为 ThingsBoard、ThingsBoard Gateway；Node-RED 和 FUXA 作为编辑交互参考。
